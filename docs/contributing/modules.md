# Modules

The services and how they hand over: [services.md](services.md). The modules below are in
`listener/` unless their path says otherwise; edge and the orchestrator each run some of them
([Edge and the orchestrator](architecture.md#edge-and-the-orchestrator)). What the services share is
in `lib/`, which every image copies beside its own code: the YAML reader and the settings parser,
redaction, HTTP helpers, the JSON state files, draining, the tokens (run and service tokens, what
each caller may do) and the store (`lib/store.mjs`, its file backend `lib/store-file.mjs`, its Redis
backend `lib/store-redis.mjs` and the Redis client `lib/resp.mjs`, the arguments both backends check
alike in `lib/store-checks.mjs`; the maps kept there one key per item, `lib/store-map.mjs`), and an
S3 client (`lib/s3.mjs`: SigV4 signing, PUT, ranged GET, HEAD and DELETE, retries on 5xx) for blob
storage (`lib/blobs.mjs`, #604: `BLOB_URL`'s S3, folder or store backends behind one interface,
checked at start). Nothing in it imports from `listener/`.

`orchestrator/server.mjs` only wires the orchestrator together: its settings, the GitHub App's
public parts, the shared `ctx` and the modules, then, once it holds its lease, it starts the
servers, restores runs and handles SIGTERM; `edge/server.mjs` does the same for edge. The stateful
modules are `createX(ctx)` factories sharing one `ctx` object (the settings, the GitHub App,
the tasks, the runs, the services); each reads `ctx` when it is called rather than when it is
created, so a module can call one created after it: a finished run (`runs.mjs`) schedules the
next one (`tasks.mjs`), which starts runs. Others take only what they use, injected, so their
tests fake it.

## Their end-to-end tests

Each module has its unit tests in `test/` (`runs.mjs`'s in `test/runs.test.mjs`…). The
orchestrator as a whole, edge in front of it and the runner beside it, is tested end to end by
the files below, in `test/`, one per area so that `node --test` runs them side by side
(#1071), each starting what it needs through `test/orchestrator-harness.mjs`: the fake `docker`
(`test/fixtures/fake-docker.sh`), the fake GitHub, the github, models and broker services, the
policy service, the egress proxy's stand-in, and `listen()`, which starts edge, the orchestrator
and the runner on them.

| File                              | What it covers                                                                                                 |

| `orchestrator-start.test.mjs`     | The orchestrator alone before it is up: a data volume it can't write, a stop while it loads its maps.          |
| `orchestrator-runs.test.mjs`      | Deliveries, the agents' credentials and providers, a repo's config and hosts, `/cancel`.                       |
| `orchestrator-writes.test.mjs`    | A run's GitHub writes and pushes through the gateways: brainstorms, projects, tokens, branches, `workflows`.   |
